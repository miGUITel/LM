# Taller 5. Solicitud de intercambio

## Qué debes hacer

Crea en `solicitud.html` un formulario para solicitar la participación de un alumno ficticio en un intercambio.

Utiliza datos ficticios. El formulario es un prototipo: no tiene que guardar ni enviar una solicitud real, ni calcular la duración a partir de las fechas.

Los códigos **RF** identifican los requisitos funcionales y los códigos **RNF**, los requisitos no funcionales de esta tarea.

## Requisitos funcionales

- **RF01. Datos personales.** Campos para introducir nombre, apellidos, teléfono de contacto y correo electrónico del alumno.
- **RF02. Destino.** Una lista desplegable para seleccionar el país de destino, con cinco países.
- **RF03. Fechas.** Un `input date` para la fecha de inicio y otro para la fecha de finalización. *Debes investigar cómo funciona.*
- **RF04. Duración.** Número de semanas de estancia, con un mínimo de 1 y un máximo de 12.
- **RF05. Alojamiento.** Botones de opción (`radio`) para elegir entre familia de acogida, residencia de estudiantes o apartamento compartido. Solo se podrá seleccionar una opción.
- **RF06. Servicios adicionales.** Casillas (`checkbox`) para solicitar desayuno, comida, cena y traslado desde el aeropuerto. Se podrán elegir varios servicios.
- **RF07. Comentarios.** Una caja de texto donde explicar sus intereses y dejar comentarios.
- **RF08. Botones.** Un botón para restablecer el formulario y otro para enviarlo.

## Requisitos no funcionales

- **RNF01. Autoría.** La página mostrará «Programado por: [nombre del autor del HTML]».
- **RNF02. Organización visual.** Agrupa los controles en tres marcos: **Información personal**, **Datos del intercambio** y **Alojamiento y servicios**.
- **RNF03. Etiquetado.** Cada control tendrá una etiqueta visible asociada.

## Qué debes entregar

1. **El archivo `solicitud.html`**, con el formulario y los requisitos anteriores, aplicando lo aprendido hasta ahora:
   - Un `head` con **al menos seis elementos de configuración**.
   - Un `body` con **al menos tres bloques semánticos**, como `header`, `nav`, `main`, `article`, `section` o `footer`, elegidos según su función.

2. **Un índice en el `README.md` del proyecto**, con una entrada enlazada a la reflexión de cada tarea realizada.

3. **La reflexión de esta tarea en el mismo `README.md`**, explicando brevemente:
   - Qué has aprendido.
   - Qué dificultades has encontrado y cómo las has resuelto.
   - Qué has probado para comprobar que el formulario funciona.
